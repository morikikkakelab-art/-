# 記事制作・公開

**スキル分類**: きっかけLab.責任者 → 子スキル  
**優先度**: ⭐⭐⭐ 最高優先度（図解画像生成含む）  
**習得期間**: 2-3週間  
**実行頻度**: 週1-2回（週1記事以上）  
**最終更新**: 2026年5月8日

---

## 📋 概要

記事制作・公開は、CEO 承認を得た HP 記事・note 記事を、実際に執筆・編集・図解生成してホームページや note プラットフォームに公開するスキルです。

**目的**:
- 企画から承認された記事を高品質で制作・公開
- わかりやすい図解画像を自動生成し、記事に挿入
- SEO/note アルゴリズム最適化を念頭に執筆
- HP と note の同時公開を効率的に実施
- CEO 最終確認フローの確立

**含まれるプロセス**:
1. 記事本文の執筆・編集
2. わかりやすい図解画像の生成（Claude 利用）
3. 記事内への画像配置・整形
4. CEO 最終確認・承認
5. HP・note プラットフォームへの公開
6. Notion への記録・管理

---

## 🎯 目標

このスキルを習得すると、以下ができるようになります：

- ✅ 企画案から記事本文を高品質で執筆
- ✅ Claude を使って図解画像生成プロンプトを作成
- ✅ 生成した画像を適切に記事内に挿入・配置
- ✅ SEO/note アルゴリズム最適化に配慮した執筆
- ✅ CEO 最終確認から公開までを 3-5 営業日で完了
- ✅ 月間4記事以上の公開を実現
- ✅ HP・note での検索流入・エンゲージメント向上

## 🔧 実行手順

### **ステップ1：記事本文の執筆**

#### 1-1. 企画案から執筆要件を整理
**実行時間**: 1-2時間（1記事当たり）

CEO 承認済みの企画案から以下を確認：
- 記事タイトル
- 記事構成（見出し案）
- 対象ターゲット層
- 目標キーワード（HP 記事の場合）
- 参考資料・引用元

```
【チェック項目】
□ タイトルが SEO キーワード含む（HP 記事）or 感情的（note 記事）
□ 見出し構成が論理的か
□ ターゲット層に有益な内容か
□ 自社の差別化ポイントが含まれているか
□ 記事の長さ目安（2000-5000字）を確認
```

#### 1-2. 本文を執筆
**実行時間**: 3-5時間（1記事当たり）

執筆時のポイント：

```
【執筆の基本】
1. 冒頭 100 字で「何が学べるか」を明確化
2. 見出しごとに 300-500 字を目安に段落分け
3. 難しい用語は初出時に説明・簡潔化
4. 実例・クライアント事例を含める
5. 最後に「チェックリスト」や「まとめ」を配置

【トーン・文体】
HP 記事：
 - 敬語・ビジネストーン
 - 「ます」調で統一
 - 客観的・教育的
 - リスト・図解での分かりやすさ重視

note 記事：
 - 親近感・個人の声
 - 「だ」「である」調も可
 - 主観的・体験ベース
 - ストーリー性重視
```

#### 1-3. 自己編集・修正
**実行時間**: 1-2時間（1記事当たり）

執筆後、自分で以下をチェック：

```
【セルフチェック項目】
□ 誤字脱字がないか（3回読み）
□ 事実に誤りがないか
□ 難しい用語を使いすぎていないか
□ 段落分けが適切か
□ 統計データ・引用が正確か
□ リンク先が正しいか（HP 記事）
□ 記事の長さが目安内か（2000-5000字）
```

### **ステップ2：図解画像の生成**

#### 2-1. 図解が必要な箇所を選定
**実行時間**: 1時間（1記事当たり）

記事内で「図解化すると分かりやすい」部分をリストアップ：

```
【図解化に適した内容】
✅ フロー・プロセス（ステップ1→2→3）
✅ 比較表（A方法 vs B方法）
✅ 構成要素・フレームワーク
✅ データ可視化（棒グラフ・円グラフ）
✅ 事例・ケーススタディの流れ
✅ チェックリスト
✅ 複雑な概念の図解

❌ 図解が不要
- 単純なテキスト説明
- 既に視覚的に分かりやすい内容
```

#### 2-2. Claude に図解画像生成プロンプトを指示
**実行時間**: 30分-1時間（1画像当たり）

Claude に以下の情報を提供して図解生成を依頼：

```
【図解生成プロンプトのテンプレート】

「以下の内容を、わかりやすい図解画像で表現してください。

【内容】
タイトル：〇〇

概要：〇〇について、以下のフロー・比較を図解してください。

詳細：
- 要素1：〇〇（説明）
- 要素2：〇〇（説明）
- 要素3：〇〇（説明）

【図解の要件】
- 形式：〇〇（フローチャート / 比較表 / 円グラフ等）
- 色：〇〇（きっかけLab.のブランドカラー：青・白・アクセント色）
- 文字：日本語、わかりやすいフォント
- サイズ：横 1200px × 縦 600-800px
- ファイル形式：PNG / SVG

補足：きっかけLab.のビジュアルブランド（色使い、フォント）に合わせてください」
```

#### 2-3. Claude から図解画像を受け取り・確認
**実行時間**: 30分（1画像当たり）

Claude が生成した図解画像を確認：

```
【確認項目】
□ 内容が記事の文脈に合致しているか
□ テキストの誤字脱字がないか
□ 色使いがきっかけLab.ブランドと合致しているか
□ 解像度・サイズが適切か（横 1200px 以上）
□ 複数の図解がある場合、デザイン統一されているか
```

修正が必要な場合は、Claude に修正指示を出す：

```
【修正指示例】
「この図解について、以下の修正をお願いします：
- 色を〇〇に変更
- テキストの文字サイズを大きく
- 余白を調整」
```

### **ステップ3：記事内への画像配置・整形**

#### 3-1. 画像ファイルを整理・保存
**実行時間**: 30分（1記事当たり）

生成された図解画像を以下の場所に保存：

```
保存先フォルダ構造：
context/きっかけLab.SNSマーケ事業/コンテンツ企画/
 ├── HP記事/
 │   ├── [記事タイトル]/
 │   │   ├── 記事本文.md (or .docx)
 │   │   ├── 画像1_フロー図.png
 │   │   ├── 画像2_比較表.png
 │   │   └── 画像3_チェックリスト.png
 └── note記事/
     ├── [記事タイトル]/
         ├── 記事本文.md (or .docx)
         ├── 画像1.png
         └── 画像2.png

【ファイル命名規則】
- 画像1_〇〇フロー図.png
- 画像2_〇〇比較表.png
- 画像3_チェックリスト.png
（順番 + 内容を明記）
```

#### 3-2. マークダウン形式で画像を記事内に挿入
**実行時間**: 1-2時間（1記事当たり）

記事本文に画像を挿入する際の形式：

```
【マークダウン形式での画像挿入】

記事本文（該当箇所）
![画像の説明](ファイルパス/画像1_フロー図.png)

（キャプション）
*図：〇〇のフロー*

---

【配置のポイント】
- 見出しの直後に挿入するのが一般的
- 画像の後に必ずキャプション（*図：〇〇*）を付ける
- 複数の画像がある場合は、図1、図2と番号付け
- 画像の幅は記事幅に合わせる（HP：800-1000px / note：600-800px）
```

#### 3-3. 記事の最終整形
**実行時間**: 1時間（1記事当たり）

記事の見た目・読みやすさを整える：

```
【整形チェック項目】
□ 見出しレベルが適切か（H2, H3 の階層）
□ 段落間隔が適切か
□ リストの階層が統一されているか
□ 画像が記事の流れに自然に配置されているか
□ テーブル（表）の形式が統一されているか
□ 引用・参考リンクが明確か
□ モバイル表示での見やすさ（note の場合）
```

### **ステップ4：CEO 最終確認・承認**

#### 4-1. CEO へ記事案を提出
**実行時間**: 30分（1記事当たり）

完成した記事を CEO に提出：

```
【提出方法】
1. Google Drive に記事ファイル + 画像を保存
2. CEO に Slack / メールで以下を送付：

件名：記事制作完了・CEO 確認のお願い：「〇〇」

本文：
以下の記事が完成いたしました。ご確認ください。

【記事概要】
- タイトル：〇〇
- 形式：HP 記事 / note 記事
- 長さ：〇〇字
- 図解数：〇〇枚
- 公開予定日：〇〇年〇月〇日

記事ファイル：[Google Drive リンク]
図解画像：[Google Drive フォルダ]

ご指摘・修正案をお願いいたします。
期待応答：2営業日以内
```

#### 4-2. CEO フィードバック対応
**実行時間**: 1-2時間（修正が必要な場合）

CEO からのフィードバック例と対応：

```
【フィードバック例1】内容修正
CEO: 「この部分のデータが古いので、最新データに更新してください」
対応: 
 1. 最新データを調査
 2. 該当箇所を修正
 3. 「修正版」として再提出

【フィードバック例2】画像修正
CEO: 「この図解、もっと分かりやすく修正できますか？」
対応:
 1. Claude に修正指示を出す
 2. 修正された画像を受け取る
 3. 記事に再配置
 4. 「修正版」として CEO へ再提出

【フィードバック例3】構成修正
CEO: 「章の順番を変更したいです。実例を先に持ってきてください」
対応:
 1. 記事構成を再編成
 2. 見出しを調整
 3. 必要に応じて画像も再配置
 4. 「修正版」として再提出
```

#### 4-3. CEO 承認・公開へ
CEO からの最終承認メール確認後：
1. Notion「記事制作」DB の**ステータス**: 「CEO 承認済み・公開待ち」に変更
2. **公開予定日**: 確定
3. ステップ5（公開）へ進む

---

### **ステップ5：HP・note への公開**

#### 5-1. HP への公開（WordPress or 自社 CMS）
**実行時間**: 1時間（1記事当たり）

```
【HP 公開フロー】

1. WordPress（もしくは自社 CMS）にログイン
2. 「新しい投稿」を作成
3. 以下を記入：
   - タイトル（CEO 承認版）
   - 本文（マークダウンから HTML に変換）
   - 図解画像をメディアライブラリにアップロード
   - アイキャッチ画像を設定
   - カテゴリ・タグを設定（SEO キーワード含む）
   - メタディスクリプション を設定（160字以内）
   - 公開予定日を設定（指定時刻に自動公開）
4. 「プレビュー」で最終確認（PC・モバイル両方）
5. 「公開」ボタンをクリック
```

#### 5-2. note への公開
**実行時間**: 1時間（1記事当たり）

```
【note 公開フロー】

1. note にログイン
2. 「創作」→「新しい記事を作成」
3. 以下を記入：
   - タイトル（CEO 承認版）
   - 本文（マークダウンから note 形式に変換）
   - 図解画像をアップロード
   - アイキャッチ画像を設定
   - カテゴリ・タグを設定
   - 有料/無料を選択
   - マガジンに追加（該当する場合）
   - 公開予定日時を設定（指定時刻に自動公開）
4. 「プレビュー」で最終確認
5. 「公開」ボタンをクリック

【公開後の対応】
- 公開後 1 時間以内：SNS（X, Threads）でシェア
- 公開後 24 時間以内：コメントを確認・返信
```

#### 5-3. Notion に記録
**実行時間**: 30分（1記事当たり）

Notion「コンテンツ管理」DB に記録：

```
【Notion 記入項目】
- 記事タイトル
- 公開形式：HP / note
- 公開日時
- URL（HP もしくは note リンク）
- ステータス：「公開済み」
- 初期アクセス数（公開24時間後に記録）
- 図解数
- キーワード（SEO キーワード）
```

## ❓ よくある質問（FAQ）

### **Q1. 図解画像の生成、どのくらい時間がかかる？**
**A.** 1 画像あたり、以下の時間が目安：

```
- プロンプト作成：10-15分
- Claude で生成：10-15分
- 修正依頼・受け取り：15-30分（修正が必要な場合 +15-30分）

合計：30分-1時間が目安
複数の画像がある場合でも、ある程度並列化できるため、1記事で2-3時間が目安
```

---

### **Q2. 記事本文は全部自分で書かないといけない？**
**A.** 以下の方法で効率化可能：

```
【効率化方法1】Claude のサポート
- 記事構成案から各セクションのドラフトを Claude に生成させる
- あなたが修正・微調整する形で最終版を作成

【効率化方法2】分担
- 図解画像生成を優先（高付加価値）
- テキストは方向性・枠組みを CEO と確認してから執筆

【推奨フロー】
1. 企画案から見出しを抽出
2. Claude に各セクションのドラフトを生成依頼
3. あなたが実例・差別化を盛り込んで修正
4. CEO に提出
5. CEO からのフィードバック対応
```

---

### **Q3. CEO からの修正要望が大きい場合、どうする？**
**A.** 以下の対応をしてください：

```
【修正の流れ】
1. CEO の要望を正確に理解する（疑問点は質問）
2. 修正箇所・修正内容を整理
3. 修正を実施
4. 修正内容がわかる形で CEO へ再提出（「修正版」と明記）
5. CEO の最終承認を取得

【大きな修正の場合】
- 一度に全修正はせず、優先順位を付ける
- CEO と相談して修正期間を延長する
- 修正期間は原則 3 日以内（相談可能）
```

### **Q4. 図解画像を複数生成する場合、デザイン統一どうする？**
**A.** Claude に以下を指示：

```
【デザイン統一の指示】
「この記事に複数の図解画像を生成します。すべてのデザインを統一してください。

【統一すべき要素】
- 色：きっかけLab.ブランドカラー（青色：#2563EB、白：#FFFFFF、アクセント：オレンジ）
- フォント：日本語フォント（游ゴシック or Noto Sans CJK）
- スタイル：モダン・シンプル（複雑な装飾なし）
- 図形：角丸長方形・矢印・円形を統一
- 余白：20-30px

画像1：フロー図（3段階）
画像2：比較表（A vs B）
画像3：チェックリスト（5項目）

すべてのデザインが統一されるよう、生成してください」
```

### **Q5. 公開後、PV が期待以下だった場合は？**
**A.** 以下の改善を検討：

```
【HP 記事の場合】
1. Google Search Console でクエリを確認
2. 検索キーワードが想定と異なる場合は、タイトル・メタディスク変更
3. 平均掲載順位が低い場合は、内容を深掘り・拡充
4. 関連記事のリンクを追加

【note 記事の場合】
1. なぜスキが少ないのか分析
   - タイトルが悪いか / コンテンツが良くないか / デザインか
2. タイトルを修正（note は途中修正可能）
3. SNS でのシェアを強化
4. 関連記事を紹介
```
