# Slack運用ガイド

**事業**: SNSマーケティング支援事業  
**責任者**: きっかけLab.責任者  
**最終更新**: 2026年5月8日

---

## 📋 概要

Slackを活用した効率的な運用フローガイド。以下の機能を実装して、営業・コンテンツ企画・記事制作・分析業務を効率化します。

**4つの主要機能**：
1. **リマインド通知** - タスク・締切管理の自動化
2. **クイック承認** - CEO承認フローの迅速化
3. **下書き相談** - クライアント対応の相談・アドバイス
4. **簡易入力** - 経費・売上・ネタ投稿の手軽な記録

**Notion連携**: Slack上での操作がNotionに自動同期

---

## 🔔 1. リマインド通知機能

### 概要
営業目標、記事納期、SNS投稿、クライアント対応などの重要なタスクを、指定日時にSlackで自動通知します。

### 使用場面

| タスク | 通知日時 | 用途 |
|--------|---------|------|
| 月間売上目標確認 | 毎月1日 08:00 | 月間売上目標の確認・進捗管理 |
| 週間商談ログ確認 | 毎週金曜 17:00 | 1週間の商談進捗をまとめて確認 |
| HP記事納期 | 記事企画承認から3営業日 | 記事制作の締切リマインド |
| note記事納期 | 記事企画承認から3営業日 | 記事制作の締切リマインド |
| SNS投稿予約確認 | 毎日 07:00 | その日の投稿予約状況確認 |
| クライアント確認 | 毎月第2週火曜 | クライアント状況のまとめ確認 |
| KPI分析 | 毎月末 17:00 | 月間KPI達成度の分析通知 |
| トレンド更新リマインド | 毎週金曜 09:00 | Notionのトレンド情報更新リマインド |

### 実装ステップ

**Step 1: Notionで通知スケジュール設定**
- `context/きっかけLab.SNSマーケ事業/運用管理/リマインダー` データベースを作成
- 項目：タスク名、実行日時、通知内容、対象ユーザー（Slackユーザー名）

**Step 2: Slack Workflowで通知実行**
- Slack Workflow Builder で定期タスクを設定
- または Claude + Slack Bot で Notion 内の予定をスキャンして通知

**Step 3: 通知メッセージのカスタマイズ**
- テンプレート例：
```
🔔 [リマインド] ○○タスク
期限: 2026年5月10日 18:00
概要: このタスクについて確認が必要です
詳細: [Notionリンク]
```

### 通知の確認・対応フロー
1. Slack通知を受け取る
2. Notionリンクをクリックして詳細確認
3. 必要に応じて対応（記事制作・投稿・報告等）
4. 完了後、Notionで「完了」をマーク

## ✅ 2. クイック承認機能

### 概要
HP記事・note記事・SNS投稿などをCEOに素早く承認してもらうSlackフロー。チャットで承認完了できるため、メール確認の手間を削減。

### 対象コンテンツ

| コンテンツ | 承認者 | 用途 |
|-----------|--------|------|
| HP記事案 | CEO | 企画段階での方向性確認 |
| HP記事最終版 | CEO | 公開前の最終確認 |
| note記事案 | CEO | 企画段階での方向性確認 |
| note記事最終版 | CEO | 公開前の最終確認 |
| 重要な投稿（クライアント案件） | CEO | SNS投稿の内容・タイミング確認 |
| 経費申請（5万円以上） | CEO | 経費決裁 |

### 実装ステップ

**Step 1: Notion投稿テンプレートを準備**
- 各記事・投稿コンテンツを構造化（タイトル・本文・画像・ステータス等）

**Step 2: Slack通知で承認リクエスト**
- Claudeが Notion から「承認待ち」ステータスのコンテンツを検出
- Slackで承認リクエスト通知を送信
- 通知にはプレビュー + 「承認」「差戻し」ボタン付き

**Step 3: CEOが Slack でワンクリック承認**
```
【承認リクエスト】 HP記事：「SNSマーケティング初心者向けガイド」

✍️ タイトル: SNSマーケティング初心者向けガイド
📝 概要: フォロワー増加の基本戦略について...
🖼️ 画像数: 3枚
作成者: Claude(責任者)
納期: 2026年5月10日

[✅ 承認] [🔄 差戻し] [💬 コメント]
```

**Step 4: 承認後の自動処理**
- ✅ 承認 → Notionの「ステータス」を「承認済み」に更新 → 記事制作フローへ
- 🔄 差戻し → 「承認待ち」に戻す → コメント内容をNotionに記載
- 💬 コメント → Slackスレッドで議論 → 修正後に再度承認リクエスト

## 💬 3. 下書き相談機能

### 概要
クライアント対応の返信文案・提案内容などをSlackで下書きして、CEOや他メンバーに相談できる機能。メール原稿を事前にレビューして、質を高めます。

### 使用場面

| 対応内容 | 用途 | 相談相手 |
|---------|------|---------|
| クライアント初期対応メール | 重要なクライアントの対応品質向上 | CEO |
| 商談提案資料の説明文 | クライアント説得力の確保 | CEO |
| クレーム・問題対応メール | クレーム対応の適切性確認 | CEO + 経理責任者 |
| SNS投稿の文案（重要案件） | ブランド維持 | CEO |
| 記事の導入文（HP/note） | 読者惹きつけ効果確認 | CEO |

### 実装ステップ

**Step 1: Slack専用チャネル「#相談」を作成**
- プライベートチャネル（CEO + 責任者のみ）
- スレッドで議論できる構造

**Step 2: 下書きテンプレートで投稿**
```
【下書き相談】 クライアント対応
相談内容: 初期接触メールの返信案

━━━━━━━━━━━━━━━━━━
【件名】 ご来社のご提案 - きっかけLab.
【本文】
いつもお世話になります。きっかけLab.の○○です。

先日のお話について、改めてご提案させていただきたく...

━━━━━━━━━━━━━━━━━━

🤔 相談ポイント：
- 提案内容は説得的か？
- 専門用語が多くないか？
- 次のアクション（会議日程提示など）は明確か？

📋 期限: 本日中に返信したいです
```

**Step 3: スレッドで議論・修正**
- CEO がコメントで指摘 → 修正提案
- スレッド内で複数の修正案を検討
- 最終版が合意したら「承認」マーク（✅）

**Step 4: 承認後の送信**
- 修正版をコピーして、クライアントにメール送信
- Slack スレッドのリンクを Notion 営業ログに記録
- 対応内容をクライアント記録に保存

## 📝 4. 簡易入力システム

### 概要
Slackの簡単なコマンドで、営業ネタ・経費・売上などを素早く記録。外出先からでも片手で情報入力できます。

### 対応する入力項目

#### A) ネタ投稿入力
**用途**: 外出先で見つけたSNSネタを素早く記録

```
/ネタ投稿 
タイトル: 「〇〇業界のトレンド」
概要: メルカリのこの機能がすごい...
プラットフォーム: X
画像: [スクリーンショット添付]
```

記録先: `context/きっかけLab.SNSマーケ事業/SNS運用/ネタ帳` (Notion)

#### B) 簡易売上入力
**用途**: その日の新規クライアント獲得・売上を記録

```
/売上入力
クライアント名: 〇〇会社
金額: ¥500,000
商品/サービス: SNS運用支援（3ヶ月）
契約日: 2026-05-08
確度: 100%（確定）
```

記録先: `context/経理・財務/売上管理/2026年5月_売上ログ` (Notion)

#### C) 簡易経費入力
**用途**: 領収書をSlackで撮影・送信して、経費を記録

```
/経費入力
カテゴリ: 交通費
金額: ¥3,500
日付: 2026-05-08
説明: クライアント打ち合わせの交通費（渋谷→表参道）
領収書: [画像添付]
```

記録先: `context/経理・財務/経費管理/2026年5月_経費ログ` (Notion)

#### D) 簡易リサーチ入力
**用途**: 記事企画時に見つけた参考情報を素早く記録

```
/リサーチ保存
テーマ: SNSマーケティング
参考URL: https://...
要点: 「〇〇が重要」という業界ニュース
活用予定: HP記事「初心者ガイド」
```

記録先: `context/一次情報・インプット/リサーチメモ` (Notion)

### 実装方法

**パターン1: Slash Command（推奨）**
- Slack App の Slash Command を設定
- Claude が Slack API で監聴
- 入力内容を自動で Notion に記録

**パターン2: 反応型ボット（代替案）**
- 特定キーワード（例「$記録」）でメッセージをスキャン
- 続くメッセージから自動抽出
- Notion に追記

### Notion連携フロー

```
1. Slack で /コマンド 入力
   ↓
2. Claude が Slack API 経由で受け取り
   ↓
3. 入力内容を自動解析
   ↓
4. Notion API 経由で該当DBに追記
   ↓
5. Slack で「✅ 記録しました」と確認返信
   ↓
6. ユーザーは引き続き業務継続
```

### 簡易入力テンプレート一覧

| コマンド | 記録先 | 必須項目 | 用途 |
|---------|--------|---------|------|
| `/ネタ投稿` | ネタ帳DB | タイトル・概要 | SNS投稿ネタ記録 |
| `/売上入力` | 売上管理DB | クライアント名・金額 | 売上記録（CEO確認） |
| `/経費入力` | 経費管理DB | カテゴリ・金額・領収書 | 経費申請 |
| `/リサーチ保存` | リサーチメモDB | テーマ・URL・要点 | 記事企画用リサーチ記録 |

### トラブルシューティング

**Q: Slackからの入力がNotionに反映されない**
- A: Notion API Key が正しく設定されているか確認。また Notion DB の API 接続を許可しているか確認。

**Q: リマインド通知が来ない**
- A: Slack Workflow の実行スケジュールを確認。または Claude のバックアップリマインダー機能が有効か確認。

**Q: Slash Command が反応しない**
- A: Slack App の Token Scopes に `commands` が含まれているか確認。

### Q&A

**Q: どの機能から始めるべき？**
A: 優先順序は以下：
1. リマインド通知（毎日の業務効率化）
2. 簡易入力（営業中の素早い記録）
3. クイック承認（記事制作の高速化）
4. 下書き相談（顧客対応品質向上）

**Q: 全機能を一度に実装するべき？**
A: 不要です。まずリマインド通知で運用習慣をつけてから、2〜3週間ごとに1機能ずつ追加してください。

**Q: CEO がSlack設定をしてない場合は？**
A: 責任者が代わりに設定し、CEO に設定完了を報告してください。
